# Перенос сайта АКО на хостинг

Чек-лист по порядку. Папку `docs/` на хостинг заливать не нужно.

## 1. Хостинг

- **PHP 8.1 или новее** с расширениями `mbstring` и `openssl` — на нём работает отправка заявок (`api/send.php`).
- **Apache** (читает файл `.htaccess`) — так работают страница 404, сжатие, кэш и переадресации.
  Подходит Beget и большинство российских хостингов. Если хостинг только на nginx — эти настройки
  делаются в его панели, `.htaccess` там не работает.
- **Сервер в России.** По 152-ФЗ персональные данные граждан РФ (имя и телефон из заявок)
  должны в первую очередь записываться в базы данных на территории России.

## 2. Перед заливкой — на своём компьютере

1. Проверить домен в `tools/seo/config.js` → `siteUrl` (сейчас стоит `https://ako-nw.ru`).
2. Запустить проверку и пересборку SEO — должно быть «No problems found»:
   ```
   node tools/seo/build.js
   ```
3. Почта для заявок — `api/config.php` (в git не попадает, хранит пароль):
   - **куда приходят заявки** — `to`;
   - **с какого ящика отправляются** — `smtp` и `from_email`.

   Сейчас всё настроено на Gmail. Gmail — сервис Google, его серверы за рубежом;
   для заявок с персональными данными лучше российский ящик (Mail.ru, Яндекс).
   Готовые настройки для них — в комментариях `api/config.example.php`.
   Пароль — **пароль приложения** из настроек безопасности ящика, не обычный пароль.

## 3. Что заливать

| Заливать | Не заливать |
|---|---|
| все `*.html` в корне (38 страниц) | `tools/` — скрипты сборки |
| `assets/`, `components/`, `js/`, `styles/` | `docs/` — эта инструкция |
| `api/` **вместе с `config.php`** | `.claude/`, `.git/`, `.gitignore` |
| `.htaccess` (файл с точкой — проверьте, что загрузился) | |
| `favicon.ico`, `favicon.svg`, `site.webmanifest` | |
| `robots.txt`, `sitemap.xml` | |

## 4. На хостинге

1. Выпустить бесплатный SSL-сертификат (Let's Encrypt) в панели хостинга.
2. Когда сайт открывается по `https://` — в `.htaccess` убрать `#` у шести строк
   в блоке «http → https» и «www.site → site». Проверить, что сайт открывается.
3. В кабинете разработчика Яндекса (developer.tech.yandex.ru) у ключа карты
   ограничить домены (HTTP Referer) адресом сайта — чтобы ключ не использовали чужие сайты.

## 5. Проверить после запуска

- [ ] Все три формы отправляют заявку и письмо приходит: окно «Оставить заявку»,
      форма на главной, форма на «Контактах». Без галочки согласия — не отправляется.
- [ ] `https://домен/какая-то-ерунда` показывает нашу страницу 404.
- [ ] `http://` и `www.` перекидывают на `https://домен` без www.
- [ ] `https://домен/index.html` перекидывает на `https://домен/`.
- [ ] Открываются `https://домен/robots.txt` и `https://домен/sitemap.xml`.
- [ ] Во вкладке браузера видна иконка сайта.
- [ ] Ссылка на сайт в Telegram показывает превью с картинкой.
- [ ] Карта на «Контактах» загружается.

## 6. Поисковики и закон

1. **Яндекс.Вебмастер** и **Google Search Console**: добавить сайт, подтвердить через
   meta-тег (коды вписать в `yandexVerification` / `googleVerification` в `tools/seo/config.js`,
   запустить `node tools/seo/build.js`, перезалить `index.html`), отправить `sitemap.xml`.
2. **Яндекс Бизнес**: карточка организации с адресом и сайтом — для поиска «оценка рядом»
   и Яндекс Карт.
3. **Роскомнадзор**: проверить, есть ли компания в реестре операторов персональных данных
   (pd.rkn.gov.ru). Если нет — подать уведомление об обработке персональных данных.
   Тексты политики и согласия на сайте — шаблон; их стоит показать юристу.
4. Если сайт встаёт на домен старого сайта — настроить переадресацию со старых адресов
   (`/uslugi/...`) на новые страницы, чтобы не потерять позиции в поиске.
